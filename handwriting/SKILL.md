# 用户字迹手写版生成

字库有两部分，都是用户本人的笔迹：
- **字母表样本** `assets/sample.jpg`（字母表 ×3、大写、数字 ×2、标点、59 个连笔对 ×2），清单 `assets/manifest.json`。
  来源：claude.ai 对话「Домашнее задание с переводом」（2026-11-20）。
- **自然连写样本** `assets/natural/z6–z13.jpg`（笔记 App 截图：提纲作业、俄语练习句、生词表）。
  `boxes.json` 是自动切出的词框，`words.json` 是逐框标注（只标拼写正确、没有涂改的词）。
  入库时每个标注词作为**整词**使用，并在字母之间的细连笔处切成 **2–10 个字母的词块**；
  词块只有在另一个词里切出的同名块形状一致时才保留（交叉验证，防止切错字母）。
  `assets/natural/n2–n5.jpg` 是低清原图，只用于测量书写习惯，不入库。
- **纸面照片样本** `assets/natural/p1.jpg`（方格本手机照片，2026-11-26：«Чем…, тем…» 7 句作业，老师有红笔 ✗），
  由 `scripts/prep_photo.py` 从原照片清理而来（去方格线、去红笔、压平光照）。p* 开头的文件不做 App 界面遮挡（CHROME）。

切好的字库是 `assets/glyphs.pkl`（`python scripts/build_glyphs.py` 生成，约 1 分钟）。

## 步骤

1. 把要写的内容存成 UTF-8 文本文件（放在会话的 scratchpad 里），格式：
   - `# 标题` → 居中一行
   - 空行 → 空一行；行首空格 → 缩进；单独一行 `====` → 换页
   - 引号 `"…"` 会自动变成 «…»，`–` 变成 `—`
2. 渲染（Windows 上用 `python`）：
   ```
   python ~/.claude/skills/handwriting/scripts/render.py 输入.txt 输出.pdf --png-dir 预览目录
   ```
   可选参数：`--paper grid|lines|plain`（默认 grid，5 mm 方格）、`--xh 2.4`（小写字母主体高度，毫米；
   默认 2.4 按用户平时的字高/行距比例定）、`--ink black|blue`（默认 black）、`--seed N`（换一种变体组合）。
3. **交付前必须自己看一遍**：用 Read 打开 `预览目录/page1.png`，再用 PIL 裁几段放大看（`render.Hand`/`layout`/`draw`
   可在 Python 里直接调用、拿到全分辨率页面）。逐词核对**每个词拼出来的字母对不对**——词块是自动切的，偶尔会错。
   查某个词用了哪些块：`render.Hand(2.4,1).segment("слово")`；看块的来源：`h.raw[key][k]["src"]`。
   发现坏块：字母表的变体在 `manifest.json` 的 `exclude` 里加 `{"unit": "...", "row": N}`；
   自然样本的词标错了就改/删 `words.json` 里那一项。然后重建字库再渲染。
4. PDF 保存到用户指定的位置（没说就放工作目录），用 SendUserFile 发给用户。
5. 脚本最后会打印 `MISSING (drawn with fallback font): …` —— 这些字符用户没写过（如拉丁字母），
   是用系统字体代替的，看起来不像用户的字。**一定要告诉用户是哪些字符**，并建议补写样本。

## 排版规则（用户确认过的，别改回去）

- **中性笔效果、黑色墨水**。不是钢笔，不要笔锋粗细变化。
- **笔画不重描**：不按中线重画、不收细。之前这样做被用户说"诡异""粗细太夸张"。
- **横轴对齐、大小一致**：每个变体量出 x 高主体（上沿/下沿），缩放到统一高度（0.8–1.25 倍内微调），
  按主体下沿落在横线上。自然样本的词先**扶正**（去倾斜）再**放平**（你写字时每个词往右上斜，拟合主体底线后拉平），排版时统一加回倾斜。
- **自然样本的基线用 `body_band()` 测**（用户 2026-11-20 指出 друзьями 和整行横轴不对齐）：
  用固定高度（字母表主体高度）的窗口找墨最密的那一段当 x 高主体，再在 ±25% 内微调。不要按"墨量超过最大值 35% 的行"测——
  像 друзья 这种 д/р/у/з 多的词，尾巴会被算进主体，底线测低，整个词就被抬高了。
- **单字母只用字母表**：自然样本里单独写的一个字母的词（я、в、с…）主体高度测不准（代词 я 还写得像大写 Я），不进字库。
- **字母朝向一致**（用户 2026-11-20 指出"字母朝向都不一样"）：每个单元（整词、词块、字母）都用
  `stroke_slant()` 按陡笔画的边缘方向**单独测倾斜**，再各自修正到 SLANT。不要用整块投影法（`slant_of`）
  测短块，对两三个字母的块会错得很离谱。
- **重叠截图去重**：同一次书写出现在两张截图里（z10/z11、z7/z8 有重叠），用图像相关性（`same_ink`）识别，
  只保留一份；交叉验证必须来自不同的书写，否则同一个切错的块会"自己验证自己"。
- **词块两端的长连笔要截短**：否则单独拿出来像一道横杠（例如 "ст-"）。
- **笔画粗细均匀**：`even_pen()` 把轮廓等距加厚/收薄到 `PEN × x 高`（PEN=0.24，用户确认过的粗细比例）。
- **按美观挑变体**：每个变体有分数（大小偏离、倾斜偏离、填死的小圈），只用最好的几个；拼词时难看的单元降权。
- **不要随机上下浮动**。
- 拼词优先级：整词 > 长词块 > 连笔对 > 单字母（DP 取单元数最少，词块略降权）。
- 书写习惯参数（`render.py` 顶部，2026-11-20 从约 600 个自然书写词测得）：倾斜 SLANT=0.32、
  词距 SPACE=0.8 x 高、词内单元间距 GAP=0.03 x 高、字形横向 XSTRETCH=1.08。

## 已知限制（如实告诉用户）

- 只有西里尔字母、数字和 `. , ? : ; « » — ( ) -`，外加少量中文词（积累、保存、通知、管理、反映、解释、意识、复制、接受、圆盘）。
  **没有拉丁字母**，`!` 等也没有。
- 词块之间、单字母之间仍是断开的；字母表来的单字母比自然连写的略工整，混用时能看出一点差别。
- 用户的 я 写得大、ы 的小圈小、Т 写成带横的 П 形、? 像 7——这是本人写法，不是 bug。

## 扩充字库

**用户发来自然书写的页面（截图）时**——最有效，优先用这种：
1. 图片存到 `assets/natural/`，文件名不要和已有的重复。分辨率要够：小写字母至少约 15 px 高（App 里放大后截图）。
2. `python scripts/natural_words.py segment <输出目录> assets/natural/新图.jpg …`，会生成带编号框的预览
   `<输出目录>/<图名>_0.png / _1.png`（上下半页），并**覆盖** `boxes.json`——所以要把全部自然样本图（旧的 + 新的）一起传进去，
   保证旧图的框编号不变（切词算法是确定的，同一张图编号不会变）。
3. 用 Read 看预览图，把每个框写的词填进 `words.json`（键是框号；一个词被拆成两个框（如 й 的短音符号）用 `"12+13"`）。
   **只标读得准、拼写正确的词**；带涂改、红笔、被 App 界面挡住、拼写有误的都跳过。
4. 重建字库，看 `assets/natural/chunk_sheet.png`（随机抽查的词块和标签），再渲染测试页核对。
5. **入库后必须把所有整词排成审核图逐个看一遍**（2026-11-20 用户指出"最后一行一看就不对劲"：
   z6 那页写得潦草，ы 像 нх，还有一个原稿就拼错的 нескольках，都被当成整词直接用了）。
   读不清、原稿拼错、词内断开一大截、带着邻词笔画的整词，从 `words.json` 删掉，记到 `_excluded` 里。
   切出来读成别的字母的词块（比如像"по"的 на、像"то"的 та），把它的 `src` 加进 `words.json` 的 `_bad_chunks`。
   标注时要按**原稿实际写的字母**核对，不要按应该怎么拼来"脑补"。

**用户发来纸上手写的手机照片时**（方格本/横线本）：先清理成白底黑字，再走上面的流程。
1. `python scripts/prep_photo.py 原照片.jpg assets/natural/pN.jpg x0 y0 x1 y1`（裁切框只留纸面，不要桌面；文件名必须 p 开头）。
   脚本：取 RGB 最大通道（蓝灰方格线在这个通道里很亮，黑墨各通道都暗）→ 压平光照 → 去长直线 →
   **滞后阈值**保留墨迹（深墨做种子，只往外长几像素把浅笔画连起来，不会顺着方格线蔓延）→ 去红笔 → 去小于 20 px 的残渣。
2. **一定要看清理结果，尤其是墨色浅的那几行**（2026-11-26：第一版用固定阈值，上半页墨浅，整词入库后笔画全成了一串点）。
   墨色深浅随页面位置变化，阈值要在最浅的那行上量（p1：浅处墨芯约 180–195，方格线 ≤150，`STRONG/WEAK/FULL = 150/95/160`）。
   残渣阈值也要量：ё 的点、句点约 30+ px，方格交叉残渣 <15 px。
3. 换了清理参数，**框编号会变**，要重新切分、对着新预览图重新标注。
4. 照片上原稿拼错的词（p1：дошдь、уровнень）、被红笔压到的词（фруктов）不标；切块抽查时，
   р 断开只剩一竖、Ч 后面的 е 被切掉、带起笔的 о 看着像 а（овощей 的 «ов»）都要进 `_bad_chunks`。
   照片样本的切块错误率比截图高，**p 开头样本的词块要全部看一遍**，不能只看随机抽查图。

**用户按清单写的字母表/连笔对**：存到 `assets/`，在 `manifest.json` 的 `images` 里加 `file` + `rows`（每行写了什么，单元用空格隔开），重建。

建议用户补写：拉丁字母 a–z / A–Z；以及更多自然书写的页面（作业、笔记都行），样本越多，能整块使用的词和词块越多，拼接越少。

依赖：Python 3 + opencv-python、numpy、Pillow、reportlab、scikit-image（本机已装；云端会话里用 `pip install opencv-python-headless scikit-image reportlab` 装）。
