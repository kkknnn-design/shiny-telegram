# 教材长期维护规则

## 用户已经确认的要求

- 永远用中文回复。
- 查阅可访问的全部历史和新增对话，根据实际学习内容分别维护教材。
- 参考 `C:/Users/zheng/OneDrive/first CC/output/pdf` 中已保存的教材和课程资料。
- 中文正文用宋体；数学公式使用规范、清晰的分式、根号、上下标、矩阵、多行对齐。代码用等宽字体，中文注释回退宋体，俄语用合适的衬线字体。
- **知识逻辑高于对话时间。** 按先修关系、概念、原理与推导、讲解型例题组织。新知识应插进适当章节，不能只追加到旧书末尾。
- 不设置自测题、练习题和答案。讲解型例题必须完整展开，不能把练习换名保留。
- 章节按学科知识体系命名，不把用户提出的问题或对话日期作为章节。用户的疑问融入概念、推导与例题。
- 参照 first CC 原教材的实际讲课思路：读取相关正文，考察概念怎样引入、例子如何推进和推导怎样衔接，不只列书名、套目录或堆知识点。没有对应原书的学科明确依据课程内容，不虚构参照。
- 正文采用连贯、克制的教材叙述，去掉“你问过”“最需要记住”等聊天式套话和机械清单。
- 封面、章标题及独立公式居中；正文两端对齐，代码等宽左对齐；统一页边距、行距、段间距、页码和标题层级。
- 国情、ОРГ、俄罗斯国家象征与人物作业不做教材。不得恢复已排除科目。
- 用户允许在确实有帮助时自行安装技能；现有技能足够时无需额外安装。

- 对话涉及的知识要沿现有课程主线检查自然延伸与同类公式族；补齐定义、等价形式、适用条件、特殊值、反例、推导及相邻应用，不能以“未明确问到”为由跳过。不要把无限扩展理解为跨越先修关系堆公式，新增内容应放入对应章节并记录为课程延伸，区别于已读来源原文。
- 行列式教学须明确展示单竖线记法与 det 的等价关系；写出元素的行列式使用 vmatrix，矩阵使用 pmatrix 或 bmatrix，向量模长使用双竖线。不得为消除过长竖线直接删去行列式边界。
- 用户已授权直接运行必要的常规维护和本地构建，不重复等待确认；环境权限限制仍如实记录，不能绕过限制。

2. 优先用对话列表与读取工具；ChatGPT 列表有数量限制时，用已登录的历史 UI 补查。标题可能与内容完全不同，必须按正文判定。
3. 本次已经对历史列表中的 123 个 ChatGPT 会话及可访问本地记录作了检查；完整性以当前来源清单和实际返回正文为准。工具返回分页时继续读取，直到已知检查点或末页。把新增读取结果保存到 `work/history/会话ID.json`，保持已有 thread、turns、items 的结构；新的本地缓存可通过 `work/export_local_history.py` 更新。打包脚本从这些持久化来源重建消息检查点，因此不能只在临时上下文中记录新内容。
4. 部分历史附件不在正文中，图片、课件缺失时记入待核对。`::chatgpt-content-reference` 也是引用占位，绝不能当作已经读取讲解正文；优先从已登录历史 UI 读取真实展示内容，区分恢复的文字讲解和仍未辨认的原图。旧回答只是待审材料，不能自动当作正确知识。
5. 同一消息重复读取时不重复写书。旧消息如果被编辑，比较内容哈希后审查变更，不只按创建时间筛选。
   哈希只说明消息是否变化，不代表内容已写入教材。对每条有教学内容的消息提取具体新增知识、例外、推导步骤、代码变体或纠错，记录在 `work/knowledge_coverage.json`，关联来源、教材章节和覆盖状态；不能以已有同名大模块判为覆盖。未解决的占位/截断/原图缺口继续保留，即使哈希未变也不能误标完成。
6. 日常咨询、个人医疗、购物、游戏价格和图像请求不自动变成新学科。若其中混有学科学习正文，要提取真正的知识部分。不得把私人医疗或财务细节写入公开式教材内容。

## 编辑准则

新增章前说明与已有章的关系。概念首次出现给中文名及必要俄语术语。公式交代符号、单位、条件和推导；例题必须有完整题面与答案。示范数据必须标为示范，不能伪装成用户测量。原题图片没核清时，重写自足的教学例题并标注其性质。

数学范围现为完整保留线代、解析几何、微积分与微分方程、概率统计、数学建模。特别是后三册，不能只围绕对话中的孤立知识点写摘要；需要参考可靠教材补出未被问到但必要的先修内容，用连贯课程主线展开。对话用于标出进度、难点及新增细节，不作为内容范围上限。

涉及当前产品、版本、医疗、法律或金融判断时，按任务需要查证；不要把历史回答中的时效性建议直接固化为教材事实。对 first CC 参考书区分“已找到”“已核目录或相关页”“已核完整内容”，不得声称完整读完数千页扫描书。

## 构建流程

运行前先把会修改的源文件复制到 `work/backups/北京时间日期/`。保留输出稳定路径；旧用户资料不移动、不删除、不自动发布。

执行环境的 Node、Python 可通过工作区依赖工具重新取得。本次路径为：

- Node：`C:/Users/zheng/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe`
- Python：`C:/Users/zheng/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe`

生成前按 PDF 技能调用一次其 artifact operation 标记，数量对应当次真实输出。随后顺序运行：

1. `node work/math_svg.cjs`：从各册提取 TeX，生成矢量公式。`work/formulas/errors.json` 必须为空。
2. `node work/prepare_formula_rasters.mjs`：给含嵌套SVG的伸缩符号公式生成高分辨率图，避免原转换器的裁剪黑条。
3. `python work/build_pdf.py`：使用宋体、矢量公式和可点击目录生成各册 PDF；可传两位编号只生成受影响册。
4. `python work/qa_pack.py`：核对 PDF、边界并渲染全页缩略图与细看页。
5. 查看最新缩略图和公式、代码、表格所在页面，修正后重建。
6. `python work/package_books.py`：更新总目录、合并 PDF、ZIP 和正式清单。

`work/render_books.mjs` 只生成离线 HTML 阅读版；PDF 构建不依赖启动浏览器。本机浏览器进程启动曾被环境限制，已改用不需浏览器的矢量排版流程。

合并与打包前检查页码、字体、目录和文件清单。中文标点允许正常悬挂标点排版；不能用它掩盖真正越界。数学图形本身也要目视检查。教材代码若未编译运行，应如实记录，不能将排版检查说成编译测试。

公式转换的已修正要点：嵌套SVG必须保留x/y、viewBox映射与视口裁剪，否则行列式及模长的伸缩竖线会过长或偏移；裁剪路径不得有可见填充/描边。SVG中的中文text须转换字形方向。行内数学使用对象替代字符供CJK断行但不印该字符；不得切换普通西文断行以掩盖错误。以后改排版需放大核对二阶行列式、三阶行列式、列向量括号和含中文说明的公式。
